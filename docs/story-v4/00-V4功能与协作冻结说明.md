# 《莲城双图：未尽之图》V4 功能与协作冻结说明

> 状态：开发冻结稿  
> 故事内容来源：`docs/莲城双图_未尽之图_完整剧本冻结稿.md`  
> 故事 ID：`lotus_city_double_map`  
> 内容版本：`4`  
> 产品形态：手机浏览器中的竖屏 Web 应用

## 1. 本版本必须实现的完整链路

1. 用户在旅行偏好页看到故事游入口；
2. 用户登录后开始故事，后端创建故事会话和对应 Trip；
3. 用户阅读开场，获得古书、城市双图、六组局部双图和第一张纸条；
4. 用户按固定路线完成六站：
   - 妈阁庙；
   - 郑家大屋；
   - 议事亭前地；
   - 三街会馆；
   - 卢家大屋；
   - 大炮台；
5. 每站先确认到达，再阅读漫画、对话和地点资料；
6. 前五站各完成一关，可请求提示、重试或跳过；
7. 每完成或跳过一关都能继续，并获得对应纸条花瓣；
8. 大炮台完成综合判断和“今日补记”；
9. 后端保存唯一完整结局，Trip 同步完成；
10. 用户退出并重新登录后可以恢复同一版本的进度。

## 2. 内容硬边界

- 标题固定为《莲城双图：未尽之图》。
- 只保留六站，不得恢复哪吒庙、旧城墙、红绫童子、莲心片等早期内容。
- 固定角色为玩家、阿莲、阿澜、M先生。
- 阿莲是随行同学、地陪和知识 Agent，不是无所不知的讲解员。
- 前五关获得五张秘密纸条中的花瓣；五张纸条迎光重合后组成澳门市花。
- 花朵中央出现“城由人共写”。
- 只有一个完整结局，不设置互相否定的好坏结局。
- 阿澜、M先生、双图、纸条和谜题属于剧情虚构；真实地点知识必须保留内容类型与来源边界。

## 3. 技术硬边界

- 后端是唯一进度真相源；前端不得自行判定通关或伪造奖励。
- 谜题答案只存后端，公开故事接口不得返回 `solution`。
- 每个故事会话记录 `content_version`；V3 会话不得被 V4 内容错误续接。
- 所有动作继续使用现有故事接口和动作模型：
  - `arrive`
  - `answer`
  - `hint`
  - `skip`
  - `continue`
  - `choose_ending`
- V4 的唯一结局在接口层仍使用 `choose_ending`，但只暴露一个选项；前端显示为“完成今日补记”，不显示为多结局选择。
- 所有章节内容、谜题、对话、知识卡、Agent 上下文和素材引用均来自故事 JSON。
- 图片只使用固定资源 ID，不把剧情逻辑写进图片。

## 4. 三部分协作边界

### 4.1 本次统一定调与后端

- 冻结文档；
- 故事 V4 数据；
- 内容版本隔离；
- 六站会话状态机；
- 六类谜题判定；
- 跳过、提示、奖励、单结局；
- 阿莲 Agent 的章节上下文；
- 后端自动化测试。

### 4.2 后续前端（陈兄）

- 只消费冻结接口，不修改后端判定；
- 默认按手机竖屏设计；
- 实现封面、开场、路线地图、章节场景、对话、谜题、奖励、结局页面；
- 为本文档规定的全部素材 ID 预留位置；
- 图片缺失时显示统一占位，不阻断功能；
- 负责前端自己的构建、交互和移动端测试。

### 4.3 后续生图与素材接入（Hongyi）

- 按素材清单逐项生成；
- 保持统一风格、尺寸、透明背景和安全区；
- 不在图片中生成大段正文或谜题答案；
- 按固定文件名交付；
- 最后替换前端占位图并做视觉检查；
- 不修改后端业务判定。

## 5. 完成定义

只有同时满足以下条件，V4 才算完成：

- 六站顺序与冻结剧本一致；
- 旧删减内容不再出现在接口和主流程；
- 前五关均支持答题、提示和跳过；
- 大炮台单结局可完成；
- 进度可恢复且不会跨内容版本串线；
- 所有公开接口不泄露答案；
- 手机宽度 360px 至 430px 可完成全流程；
- 图片未到位时仍可纯文字完成；
- 后端测试、故事数据校验和前端构建全部通过。
