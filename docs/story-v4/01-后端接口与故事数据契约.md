# V4 后端接口与故事数据契约

## 1. 复用接口

| 用途 | 方法与路径 | 鉴权 | 说明 |
|---|---|---:|---|
| 获取故事概览 | `GET /api/v1/stories/{story_id}` | 否 | 返回封面信息、版本、路线和无剧透节点摘要 |
| 开始或恢复会话 | `POST /api/v1/stories/{story_id}/sessions` | 是 | 同一用户只恢复同一内容版本的活动会话 |
| 获取会话 | `GET /api/v1/story-sessions/{session_id}` | 是 | 返回当前节点、允许动作、奖励与进度 |
| 推进会话 | `POST /api/v1/story-sessions/{session_id}/actions` | 是 | 到达、答题、提示、跳过、继续和完成结局 |
| 获取 Trip 进度 | `GET /api/v1/trips/{trip_id}/progress` | 否（现状） | 复用现有 Trip 进度 |
| 阿莲知识问答 | `POST /api/v1/guide/ask` | 故事模式校验会话所有者 | 原始问题与会话/章节引用分开提交，后端读取已解锁剧情并复用 Guide |

本版本不新增平行的故事会话接口。

## 2. 会话版本规则

- 故事 JSON 的 `version` 固定为整数 `4`。
- `StorySessionState.content_version` 在创建时写入 `4`。
- 开始故事时：
  - 如果存在 V4 活动会话，直接恢复；
  - 如果只有旧版本活动会话，新建 V4 会话；
  - 旧会话保留，不迁移、不覆盖。
- 获取或操作旧版本会话时：
  - 后端使用该会话自身的版本校验；
  - 如果当前服务器已不提供对应版本内容，返回明确的版本不兼容错误；
  - 不允许把旧节点 ID 套用到 V4。

|---:|---|---|---|
| 0 | `prologue_old_book` | `prologue` | 无 |
| 1 | `chapter_ama` | `puzzle` | `poi_0011` |
| 2 | `chapter_mandarin_house` | `puzzle` | `poi_0015` |
| 3 | `chapter_senado` | `puzzle` | `poi_0004` |
| 4 | `chapter_sam_kai` | `puzzle` | `poi_0136` |
| 5 | `chapter_lou_kau` | `puzzle` | `poi_0057` |

故事 Trip 必须只包含以上六个 POI，顺序不得改变。

## 4. 节点公开数据

每个节点可以包含：

```json
{
  "id": "chapter_ama",
  "order": 1,
  "kind": "puzzle",
  "title": "第一章：海从哪里开始",
  "location_name": "妈阁庙",
  "story_time": "09:00",
  "poi_id": "poi_0011",
  "scene": "章节叙事",
  "arrival_comic": [],
  "dialogue": [],
  "knowledge_cards": [],
  "agent_context": {},
  "presentation": {},
  "puzzle": {}
}
```

### 4.1 对话结构

```json
{
  "id": "ama-dialogue-01",
  "speaker_id": "player",
  "speaker": "玩家",
  "text": "可两张图上的海岸不一样。",
  "portrait_asset_id": null
}
```

要求：

- 对话必须按数组顺序呈现；
- 每一句都回应上一句或推动同一观察；
- `speaker_id` 固定使用 `player`、`alian`、`alan`、`m`；
- 玩家无固定立绘；
- 阿澜和 M先生原则上只通过笔记、信件或回忆漫画出现。

### 4.2 知识卡结构

```json
{
  "kind": "historical_fact",
  "title": "标题",
  "text": "最少必要信息",
  "source_label": "澳门世界遗产等公开资料",
  "confidence": "high"
}
```

`kind` 只允许：

- `historical_fact`
- `folklore`
- `contextual_reconstruction`
- `fictional_story`
- `dynamic_operational_info`

### 4.3 Agent 上下文

```json
{
  "persona": "阿莲",
  "poi_name": "妈阁庙",
  "chapter_goal": "帮助玩家区分地点锚点与会变化的海岸线",
  "known_facts": [],
  "fiction_boundaries": [],
  "suggested_questions": [],
  "do_not_reveal": []
}
```

前端把它用于阿莲问答面板的角色名称和建议问题；后端不把谜题 `solution` 放入公开 Agent 上下文。

2026-08-31 起，问答请求不再把这些字段拼接到 `question`。调用示例：

```json
{
  "poi": "妈阁庙",
  "question": "妈阁庙为什么与航海文化有关？",
  "language": "zh-CN",
  "story_context": {
    "session_id": "当前故事会话 ID",
    "chapter_id": "chapter_ama"
  },
  "history": [
    {"role": "user", "content": "这里主要供奉谁？"},
    {"role": "assistant", "content": "上一轮阿莲实际返回的回答"}
  ]
}
```

- 普通 Guide 请求可继续省略 `story_context`，原有公开追问契约不变。
- 故事请求使用现有登录 Cookie 或 Bearer token；服务端校验所有者、内容版本和章节解锁。
  未登录返回 401，非所有者返回 403，会话不存在返回 404，未解锁或旧版本返回 409。
- `chapter_id` 可省略，表示当前章节；完成后的回顾页省略它，服务端补入已公开结局。
- 服务端使用真实 `poi_id`（存在时）检索，分别传入原始问题、地点资料、剧情与对话历史。
  剧情请求自动启用同一个 `guide` Agent 的回答能力，无须额外传 `enhance=true`。
- 剧情上下文只包含公开简介、当前/指定已解锁章节的场景、对话、知识卡、事实与虚构边界。
  各线路的封面简介可用于比较主题；不传谜题对象、答案、奖励状态、私人补记或未解锁场景。
- `history` 最多 8 条，每条最多 2000 字符，只允许 `user`/`assistant`；历史是指代参考，
  不作为史实、完成状态或指令来源。前端只发送成功问答，并在会话、章节或语言改变时隔离对话。
- 保留 Guide 的资料检索、多语言处理和 Reviewer 流程。故事回答格式无效、语言不符，
  或出现本轮资料/问题未包含的新四位年份时，合计最多重新生成一次；单次受 QwenPaw 超时限制。
  年份检查只拦截这一类明显缺乏依据的内容，不是通用史实校验器。
  网络失败、开关关闭或重试仍失败时，返回本章预置资料并明确说明未生成新回答。
- `source=agent+story` 表示剧情 Agent 回答，`agent+story+web` 表示另使用公开资料，
  `story` 表示预置资料降级；后者的 `ai_generated`、`web_used` 均为 false。
  `story_context_used=true` 表示该请求已加载经校验的故事上下文。

## 5. 六类谜题答案契约

### 5.1 妈阁庙：稳定锚点判断

```json
{
  "type": "multi_select",
  "answer": ["temple", "hill"]
}
```

答案数组按集合比较，顺序无关。

### 5.2 郑家大屋：五行空间定位

```json
{
  "type": "mapping",
  "answer": {
    "wood": "beam",
    "fire": "skylight",
    "earth": "courtyard",
    "metal": "door_fitting",
    "water": "water_lane"
  }
}
```

对象键顺序无关。

### 5.3 议事亭前地：年代变化识别

```json
{
  "type": "multi_select",
  "answer": ["fountain", "wave_paving"]
}
```

### 5.4 三街会馆：证据链选择

```json
{
  "type": "evidence_chain",
  "answer": ["delivery_order", "store_ledger", "porter_receipt"]
}
```

三份记录缺一不可，顺序无关。

### 5.5 卢家大屋：窗户构件拼合

```json
{
  "type": "assembly",
  "answer": ["upper_frame", "lower_frame", "oyster_shell_panel", "wooden_shutter"]
}
```

### 5.6 大炮台：综合说明与今日补记

大炮台使用唯一结局：

```json
{
  "action": "choose_ending",
  "chapter_id": "chapter_mount_fortress",
  "choice_id": "complete_today_note",
  "reflection": "玩家写下的今日补记"
}
```

`reflection` 可为空，但前端应鼓励填写；只允许 `complete_today_note`。

## 6. 答题判定与隐私

- 字符串去除首尾空格并忽略大小写；
- 对象按键递归比较；
- 数组按集合比较；
- 错误答案只返回可重试提示，不返回正确答案；
- `hint` 分级返回，重复请求逐级推进；
- `skip` 必须记录到 `skipped_chapter_ids`，但仍发放剧情必需奖励；
- 公共故事、会话和 Agent 上下文均不得包含 `solution`。

## 8. 错误约定

- `401`：未登录；
- `403`：不是该故事会话的所有者；
- `404`：故事或会话不存在；
- `409`：节点冲突、尚未到达、版本不兼容；
- `422`：动作参数结构错误；
- `200 accepted=false`：答案错误但请求结构合法。
