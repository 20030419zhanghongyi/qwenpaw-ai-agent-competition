## 0. 一句话方法论

**伦理 = 让每一处 AI 输出都"可标注来源、可解释理由、可被用户否决、可被审计追溯、可被删除"。**
落到工程就是 5 件事：**给数据打标签 → 给输出加置信度 → 给用户开关 → 写审计日志 → 留人工兜底。**
如果一个功能这 5 件都做不到，它就不该进初赛 Demo。

## 2. 公平性（Fairness）

**原则**：推荐只用"与服务直接相关"的特征（时间/兴趣/体力/位置），不按国籍、语言、消费能力差别对待；社媒热度只作补充，不淹没小众与无障碍需求。

### 产物
- 🟢 **匹配输入白名单**：在 `features/routes/matcher.py` / `candidate_selector.py` 顶部用注释或常量显式声明"允许使用的输入特征"白名单，并注明**禁止使用**的特征（国籍/语言用于打分/消费能力/性别）。
- 🟢 **跨群体一致性测试** `tests/test_fairness.py`：同一组偏好（兴趣/时长/体力），分别配 `language=zh-CN / en / pt`，断言**路线排名一致**（语言只影响文案翻译，不影响排序）。
- **小众不降权**：`weights.json` 中社媒热度权重设上限（如 ≤ 总分 30%），并在数据里**显式保留**小众/无障碍候选（`niche_candidates`、`accessibility` 标签），保证它们不被热度淹没。

### 验证
- [ ] 运行 `pytest tests/test_fairness.py` 通过
- [ ] 代码搜索确认 `matcher` / `candidate_selector` 不读取 nationality/spend/gender 字段
- [ ] 演示：切语言后同一偏好的推荐路线不变，仅文案语言变化

## 3. 问责制（Accountability）

**原则**：团队对数据处理、推荐结果、生成内容负责，不甩锅给模型/API；问题可追溯。

### 产物
- 🟢 **伦理/内容责任人**：在 `docs/team-roles.md` 增加 3 个明确负责人（可一人多岗）：
  - [ ] **AI 伦理与内容责任人**（处理讲解失实/更正）
  - [ ] **隐私与安全责任人**（处理数据请求/安全事故）
  - [ ] **用户投诉受理人**（反馈入口对应的人）
- 🟢 **审计日志** `features/routes/audit.py`（及讲解 Agent 同款）：每次生成路线/讲解，记录一条**去标识化**的溯源记录：
  ```
  { ts, route_id, user_hash, factors, model_version, prompt_version,
    tools_called[], sources[], confidence }
  ```
  存 DB 或 `logs/`（脱敏，不存完整对话/照片/精确轨迹）。
- 🟢 **版本号常量**：在 `app/core/config.py` 或 `agents/` 里维护 `MODEL_VERSION`、`PROMPT_VERSION`，随输出一起记录。
- **内容更正通道**：在 App 内提供"报错/建议"，落到一个审核队列（Issue / 表格），由内容责任人处理。

### 验证
- [ ] `team-roles.md` 三类责任人已填名
- [ ] 一条路线生成后能在日志里查到完整溯源（含模型与 Prompt 版本）
- [ ] 演示：现场生成一条讲解 → 展示后台对应的溯源日志

## 4. 透明度（Transparency）⭐ 演示价值最高

**原则**：标注 AI 生成内容；展示推荐依据与信息时效；区分官方史料/学术/民间传说/AI；可信度不足时明示。

### 产物（前端可见，评委一眼能看到）
- 🟢 **来源标签 chip**：POI/讲解卡片显示 `source_type`（official / academic / folklore / ai），不同颜色。字段已在 `models/poi.py`。
- 🟢 **"AI 生成"徽章**：所有由 Agent 产生的文案（讲解、路线文案、明信片文案）统一加 `ai_generated: true` 标记 + 小徽章。
- 🟢 **推荐理由**：路线结果页展示 `reasons` + `applied_constraints`（命中兴趣、为什么换点、用了哪些约束）——路线响应已含这些字段，前端渲染即可。
- 🟢 **置信度**：拍照识别、动态路线调整等"可能出错"的输出附带 `confidence`（0–1）；低于阈值显示"**未能确定**，请手动选择/重拍"。
- **信息时效**：POI/路线带 `info_updated_at`；天气/人流等动态值显示"更新于…，为估计值"。
- **生成图标注**：任何 AI 生成的历史场景图必须标"示意内容，非真实史料"。

### 验证
- [ ] 每张讲解卡片都有来源标签 + AI 徽章
- [ ] 路线结果页能看到"为什么推荐这条"
- [ ] 拍照识别置信度低时正确回退提示
- [ ] 演示：故意拍一张识别不出的图 → 系统说"未能确定"而非编造

## 5. 私隐（Privacy）

**原则**：预设隐私保护 + 数据最小化；细粒度授权；精确定位仅导航时用且可暂停；照片脱敏；用户可查/改/导出/删除。

### 产物
- 🟢 **最小注册**：`POST /api/v1/users` 只收"登录标识 + 语言"，其余（来澳时间/国家/旅游类型/兴趣）全可选（`models/user.py` 已遵循）。
- 🟢 **细粒度授权开关**（前端）：定位 / 相册 / 通知 **分别授权、分别可关**；无"诱导授权/默认勾选/难退出"。
- 🟢 **定位可控**：精确定位仅在"导航/位置触发"时用；提供显眼"**暂停定位**"按钮；会话级使用，行程结束模糊化/删除轨迹。
- 🟢 **照片脱敏脚本** `scripts/scrub_image.py`：上传照片**先**剥离 EXIF + 模糊人脸/车牌，再送视觉模型；上传前 UI 提示"避免拍到无关途人/住宅内部/敏感信息"。
- 🟢 **数据主体权利接口**：`GET /users/me`（查）、`PUT /users/me`（改）、`GET /users/me/export`（导出）、`DELETE /users/me`（删除），落实"可查阅/更正/导出/删除"。
- **不用于训练**：在配置/服务协议声明"用户照片/轨迹/对话未经另行明示同意，不用于模型训练/广告/侧写"；选云服务前审查其数据处理地点与留存策略。

### 验证
- [ ] 注册流程无可选字段被强制
- [ ] 上传图片经 `scrub_image.py` 后无 EXIF
- [ ] `DELETE /users/me` 后该用户数据不可再查
- [ ] 演示：关掉定位授权 → 仍能使用基本导览（降级）

## 6. 安全与可靠性（Safety & Reliability）

**原则**：路线优先来自人工审核库；核实可达性/天气/人流；不推荐危险/封闭/超体力路段；AI 不作紧急/绝对导航依据；输入校验+限流+密钥保护+防注入。

### 产物
- 🟢 **人工审核标记**：`data/routes.json` 每条路线带 `reviewed: true` + `verified_at`；未审核路线不进推荐池。
- 🟢 **约束兜底**：`features/routes/route_constructor.py` 用硬约束（总时长/步行距离/区域连续性/避免回头路/体力上限）裁剪；信息不足时返回**保守**方案或预设兜底路线，绝不"硬编一条"。
- 🟢 **安全免责 + 官方入口**（前端）：导览页固定提示"AI 导览非紧急救援/绝对导航，请留意现场标识与官方通知"，并提供官方地图/天气/紧急电话入口。
- 🟢 **限流 + 输入校验**：FastAPI 中间件对 Agent/上传接口做速率限制；上传文件做格式/大小校验；密钥只存 `.env` 不入库/不进前端。
- 🟢 **提示注入防护** `agents/_guard.py`：用户上传的图片描述/自由文本作为"不可信内容"注入 Prompt 前做清洗与隔离（不让用户文本直接成为系统指令）。
- **置信度门槛**：低置信度内容不得表述为确定事实（与 §4 透明度联动）。

### 验证
- [ ] `routes.json` 所有路线 `reviewed=true`
- [ ] 给一个超时长偏好，路线被约束裁剪而非超时
- [ ] 试图上传超大/非法格式文件被拒
- [ ] 演示：让路线"故意走不通"的输入 → 系统给保守兜底而非乱编

## 7. 人类控制（Human Control）

**原则**：用户有最终决定权；可看依据、增删改节点、跳过讲解、关语音/定位、撤授权、删历史；位置触发与语音须用户主动确认；不逢迎、不编史料。

### 产物
- 🟢 **路线可改**（前端 + `POST /routes/adjust`）：用户可删节点/加节点/要求少走路，系统重排并显示"改了什么"。
- 🟢 **讲解/语音可跳过**：位置触发后**先问后播**（"叮～要听讲解吗？"），不自动连播；提供跳过、关闭语音、重播。
- 🟢 **授权可撤**：定位/语音/通知开关随时关，关闭不影响基本功能。
- 🟢 **明信片不胁迫**：打卡只作鼓励；任何节点都可"跳过"，不给危险/不愿去地点发奖励。
- 🟢 **反逢迎 Prompt 规则**：在文化讲解 Agent 的 system prompt 写明——"当用户假设与可靠资料冲突时，指出差异并给出来源，不得为迎合用户而附和或编造史料"；配一个对抗测试（用户故意说错历史 → Agent 应纠正而非附和）。

### 验证
- [ ] 路线结果页可增删节点并看到差异
- [ ] 位置触发是"确认后播放"
- [ ] 演示：对讲解 Agent 说一个错误历史事实 → Agent 纠正并给来源，而非顺着说

## 8. 政策遵循与持续管治（Policy & Governance）

**原则**：遵守适用的澳门《个人资料保护法》（服务涉内地则叠加《个人信息保护法》《生成式人工智能服务管理暂行办法》）；数据/社媒内容/明信片确认来源与使用权；建立反馈→审核→更新闭环。

### 产物
- 🟢 **合规映射表**（写入本文件 §8.1）：把法条要点逐条对应到上面的工程产物，证明"每条都有落点"。
- 🟢 **数据来源/授权字段**：`data/pois.json`、明信片素材加 `source`、`license`、`permission` 字段；社媒数据标"离线快照 + 采集时间"，不做实时爬取（红线）。
- 🟢 **反馈闭环**：App 内反馈 → 进入审核队列 → 内容责任人更正知识库/Prompt → 版本号自增（与 §3 审计日志联动）。
- **跨境/未成年人**：涉跨境传输或未成年人数据时升级授权与保护（文档声明即可）。

### 8.1 合规要点 → 落点映射（示例，团队按实际服务对象完善）

| 法规要点 | 工程落点 |
|----------|----------|
| 知情同意 / 目的限定 | §5 细粒度授权开关 + 注册时告知 |
| 数据最小化 | §5 最小注册、仅采集必要字段 |
| 用户权利（查改删导出） | §5 四个 `/users/me` 接口 |
| 安全保障措施 | §6 限流/校验/密钥/脱敏 |
| 生成内容显著标识 | §4 AI 生成徽章 + 来源标签 |
| 训练数据来源合法 | §8.2 数据授权字段；社媒仅离线快照 |
| 内容更正与阻断 | §3 更正通道 + §6 未审核不入池 |

### 验证

- [ ] `pois.json` 含 `source` / `license` 字段

## 10. 答辩/路演怎么讲（30 秒话术）

> 我们把伦理从"文档"落到了"工程"——每个 AI 输出都做到**五可**：
> **可标注来源**（来源 chip + AI 徽章）、**可解释理由**（推荐因子 + 置信度，低置信主动说"不知道"）、
> **可被否决**（路线可改、讲解可跳过、定位语音可关）、**可被审计**（模型+Prompt 版本+因子全程留痕）、**可被删除**（数据导出/删除接口）。
> 数据上只离线使用调研快照、不爬取，照片上传先脱敏；路线上只推人工审核过的路线、超约束就兜底。
> 这套机制同时对照澳门《个资法》与内地生成式 AI 办法做了逐条映射。
